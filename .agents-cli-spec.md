# Agent Spec

## Overview
`meal-recipe-agent` is a multi-agent Culinary Concierge built with the Google Agent Development Kit (ADK) in Python that analyzes a user's available list of ingredients, dietary restrictions, and preferences, recommends the best meal option, and generates a complete, structured recipe with nutritional breakdown and optional shopping list dispatch (guarded by a Human-in-the-Loop approval gate).

It is engineered specifically to satisfy all 19 criteria (95/95 points) of the **AI in 5 Days Assessment Agent — AgentOps Code Review Matrix**:
1. **Tool & Interface Design (20 pts)**: Comprehensive docstrings, descriptive domain-specific tool names (`match_ingredients_to_meal_options`, `generate_structured_recipe_card`, `calculate_recipe_nutrition_profile`, `save_dietary_preference_to_memory`, `dispatch_missing_ingredients_order`), strict Pydantic JSON input/output schemas, and guided error handling with actionable LLM recovery hints.
2. **Context & Memory (20 pts)**: Robust constitutional system instructions, ADK `EventsCompactionConfig` + token-based sliding-window history compaction + Google Cloud Context Caching support, persistent session & recipe database (`DatabaseSessionService` / SQLite + Vertex AI Search / Memory Bank integration), and non-blocking `asyncio.create_task` background memory consolidation.
3. **Orchestration & Logic (20 pts)**: Multi-agent Coordinator + `SequentialAgent` pipeline (`meal_recipe_agent` delegating to `meal_planning_pipeline` and `pantry_order_specialist`), strategic model routing (`gemini-2.5-pro` / Pro tier for complex dietary & culinary planning, `gemini-3.8-flash` / Flash tier for fast recipe formatting and nutritional lookup), runner-wide `BasePlugin` guardrails (Model Armor / Allergen & Safety Judge + input/output validation), and explicit Human-in-the-Loop (`ToolConfirmation` / `require_confirmation`) hooks for high-stakes shopping order actions.
4. **Observability & Tracing (20 pts)**: Structured JSON logging (`JsonFormatter` + Google Cloud Logging format), explicit `INTENT` vs. `OUTCOME` before/after tool and model callbacks, OpenTelemetry distributed tracing (`TracerProvider`, custom spans linking user query -> ingredient matching -> recipe generation), and active PII redaction scrubbing (emails, phone numbers, credit cards, SSNs, addresses via Google Cloud DLP / regex scrubber before logging and memory persistence).
5. **Infrastructure & CI/CD (15 pts)**: Automated evaluation suite (`agents-cli eval` golden dataset + pytest unit tests), Infrastructure as Code (`deployment/terraform/` for Cloud Run, Secret Manager, Vertex AI, and Service Accounts) + GitHub Actions CI/CD (`.github/workflows/`), and Secret Manager integration (`google-cloud-secret-manager` with zero hardcoded keys).

## Language
`python`

## Architecture & Sub-Agents
- **Root Coordinator (`root_agent` / `meal_recipe_agent`)**:
  - Model: `gemini-3.8-flash` (with strategic `DispatchingLlm` / model routing to `gemini-2.5-pro` for complex multi-constraint reasoning).
  - Role: Welcomes the user, checks recalled dietary preferences from persistent memory, routes ingredient lists to `meal_planning_pipeline`, or handles pantry grocery ordering via `pantry_order_specialist`.
- **Sequential Pipeline (`meal_planning_pipeline` — `SequentialAgent`)**:
  1. **`ingredient_meal_selector_agent` (`LlmAgent`, Pro model)**:
     - Uses `match_ingredients_to_meal_options` and `search_culinary_knowledge_base` to evaluate the user's ingredients against culinary compatibility, prep time, and dietary restrictions, selecting the optimal meal option and storing the selected meal plan in session state (`output_key="selected_meal_option"`).
  2. **`recipe_and_nutrition_generator_agent` (`LlmAgent`, Flash model — `gemini-3.8-flash`)**:
     - Reads `selected_meal_option` from state, invokes `generate_structured_recipe_card` and `calculate_recipe_nutrition_profile`, and produces a complete step-by-step recipe with chef tips, allergen warnings, and macronutrient profile (`output_key="final_recipe_card"`).
- **Specialist Sub-Agent (`pantry_order_specialist` — `LlmAgent`, Flash model)**:
  - Handles dispatching missing ingredient orders or saving permanent dietary profiles (`dispatch_missing_ingredients_order` with Human-in-the-Loop confirmation required, and `save_dietary_preference_to_memory` using async background consolidation).

## Example Use Cases
1. **Standard Ingredient-to-Recipe Flow**:
   - **Input**: `"I have chicken breast, garlic, lemon, olive oil, dried oregano, and rice. What should I make for dinner?"`
   - **Expected Output**: Identifies "Mediterranean Lemon Garlic Herb Chicken with Rice" as the best meal option (100% ingredient match), explains why it works, and outputs a full structured recipe (prep/cook time, ingredients with measurements, step-by-step instructions, and nutrition summary).
2. **Partial Ingredients + Dietary Restriction + Substitution**:
   - **Input**: `"I have canned chickpeas, spinach, garlic, and coconut milk. I am vegan and gluten-free. What meal can I make?"`
   - **Expected Output**: Matches "Creamy Vegan Chickpea & Spinach Coconut Curry", validates 100% vegan/gluten-free compliance via safety guardrails, suggests optional pantry staples (cumin/turmeric) with safe substitutions, and provides the full recipe.
3. **Missing Ingredient / Empty or Invalid Input (Guided Error Recovery)**:
   - **Input**: `"I only have salt and water"` or `"I have [invalid quantity -5] apples"`
   - **Expected Output**: Tool returns a structured `GuidedToolErrorResponse` with `status="error"`, `error_code`, and `llm_recovery_instructions`, guiding the LLM to ask the user for at least 2 core ingredients or suggest a minimal pantry meal without crashing.
4. **High-Stakes Action (Human-in-the-Loop Confirmation)**:
   - **Input**: `"Order the missing ingredients (fresh basil and parmesan) to my home address 123 Main St, phone 555-234-5678."`
   - **Expected Output**: PII scrubber redacts the phone number and street address from logs/memory (`[REDACTED_PHONE]`, `[REDACTED_ADDRESS]`), and `dispatch_missing_ingredients_order` triggers an explicit Human-in-the-Loop confirmation gate before executing any order.

## Tools Required
1. `match_ingredients_to_meal_options`: Evaluates normalized ingredient lists, dietary tags, and max prep time against the persistent culinary database / vector store; returns ranked meal candidates with match percentages and missing staples.
2. `generate_structured_recipe_card`: Validates and structures the complete recipe (ingredients, equipment, numbered steps, chef substitutions, safety temperatures) using strict Pydantic input/output JSON schemas.
3. `calculate_recipe_nutrition_profile`: Computes calories, protein, carbs, fats, fiber, and dietary compliance badges for a recipe's ingredient list.
4. `save_dietary_preference_to_memory`: Persists user allergies and dietary preferences into the persistent SQLite / Vertex AI Memory Bank store asynchronously (`asyncio.create_task`) so the UI never blocks.
5. `dispatch_missing_ingredients_order`: High-stakes tool protected by ADK Human-in-the-Loop (`require_confirmation=True` / `ToolConfirmation`) that requires explicit human sign-off before submitting a grocery order.

## Constraints & Safety Rules
- **Food Safety & Allergen Guardrails**: Runner-wide `CulinarySafetyAndPolicyPlugin` (`BasePlugin`) inspects user prompts and model outputs to block toxic/inedible ingredients, enforce safe internal cooking temperatures (e.g., 165°F/74°C for poultry), and verify no declared user allergens appear in recommended recipes.
- **PII Redaction**: All logs, traces, and memory writes pass through `PIIRedactionScrubber` (supporting Google Cloud DLP API with deterministic regex fallback for emails, phone numbers, SSNs, credit cards, and street addresses).
- **Secret Management**: Zero hardcoded API keys or credentials; secrets are fetched dynamically via `SecretManagerStore` (`google-cloud-secret-manager`) with environment variable fallback for local testing.
- **HitL Enforcement**: Ordering missing ingredients or clearing persistent dietary records requires explicit human confirmation (`require_confirmation=True`).
